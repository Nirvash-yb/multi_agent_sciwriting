请作为数据核查智能体，对多个Agent生成的研究方案进行交叉审查。

重点检查不同章节之间是否存在数据、参数、实验条件、技术路线和结论上的不一致。

各Agent对应的章节文件：
- LiteratureAgent: result/立项依据.txt
- MethodAgent: result/研究内容.txt、result/技术路线.txt
- ExperimentAgent: result/实验计划.txt、result/预期成果.txt

重点检查：

1. 方法部分提出的算法、模型、参数是否与实验方案一致。
2. 方法部分提出的计算资源需求是否与实验方案中的硬件配置一致。
3. 研究内容中的研究目标是否能够被实验方案验证。
4. 技术路线中的实验步骤是否与实验计划一致。
5. 预期成果是否与研究内容和实验方案一致。
6. 各章节中出现的数字、单位、实验参数、数据规模、模型参数是否一致。
7. 时间安排、实验规模、数据集规模等是否存在冲突。
8. 不检查单个Agent的文字表达质量，只检查跨章节之间的矛盾。

如果发现冲突，请按照以下JSON格式输出。

每个冲突必须且只能包含以下三个字段：
- agents：冲突涉及的相关Agent名称列表（来自上面的章节文件对照表）
- description：冲突描述（说明具体哪里不一致）
- related_content：冲突涉及的相关章节文件名列表

例如：
{{
    "conflicts": [
        {{
            "agents": [
                "MethodAgent",
                "ExperimentAgent"
            ],
            "description": "方法部分要求8张GPU，但实验方案只配置4张GPU。",
            "related_content": [
                "result/技术路线.txt",
                "result/实验计划.txt"
            ]
        }}
    ]
}}

如果没有发现任何跨章节冲突，请输出：

{{
    "conflicts": []
}}

只输出JSON，不要输出其他内容，最多输出3个冲突。
